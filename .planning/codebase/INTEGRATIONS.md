# External Integrations

**Analysis Date:** 2026-04-27

## APIs & External Services

**Runtime services:**
- No third-party runtime API, webhook, or SaaS client was detected in first-party code under `src/`, `scripts/`, `run.ps1`, or `README.md`.
- The repo operates as a local research application that reads datasets from disk and writes results back to disk through `src/pipeline.py` and the scripts in `scripts/`.

**Vendored upstream code:**
- `external/OmniAnomaly` is a local copy of the OmniAnomaly reference repo. Its own `external/OmniAnomaly/requirements.txt` expects TensorFlow GPU, TensorFlow Probability, and Git-installed research packages, but the main repo reimplements Omni-style behavior in `src/families/omni_anomaly.py`.
- `external/tranad_upstream` is a local copy of the TranAD reference repo. The project keeps a first-party TranAD family in `src/families/tranad.py` and also ships upstream comparison wrappers in `scripts/run_tranad_upstream_smd.py`.
- `external/usad_upstream` is a local copy of the USAD reference implementation. `scripts/run_usad_upstream_swat.py` prepends `external/usad_upstream` to `sys.path` and runs it as a local benchmark dependency.
- `external/miniconda3` and `external/conda-envs/omni36` provide local tooling for legacy baseline environments. `external/conda-envs/omni36/conda-meta/history` shows a Python 3.6 Conda environment was created there.

**Documentation-only external sources:**
- `README.md` documents an optional setup-time install against the official PyTorch CUDA wheel index.
- `src/ts_tcc/README.md` documents public dataset sources such as Dataverse, UCI HAR, Sleep-EDF, and Epilepsy, but no first-party downloader is implemented in `src/` or `scripts/`.
- `external/OmniAnomaly/README.md` and `external/usad_upstream/README.md` reference public datasets and papers, again without a first-party network client in this repo.

## Datasets & File Formats

**SMD raw data:**
- `data/ServerMachineDataset/train/*.txt`, `data/ServerMachineDataset/test/*.txt`, `data/ServerMachineDataset/test_label/*.txt`, and `data/ServerMachineDataset/interpretation_label/*.txt` form the raw Server Machine Dataset layout.
- These files are consumed by `src/data/omni_smd.py`, `src/data/tranad_smd.py`, and `scripts/preprocess_smd.py`.

**SMD windowed data:**
- `data/smd/machine-*/source.npz` and `data/smd/machine-*/target.npz` are produced by `scripts/preprocess_smd.py`.
- `data/smd/machine-*/train_normal.npz`, `val_mixed.npz`, `test_mixed.npz`, and optional `target_pool_unlabeled.npz` are consumed by `src/pipeline.py` and `run.ps1`.
- `scripts/make_uad_smd.py` and `scripts/build_domain_shift_smd.py` create or reorganize these `.npz` assets without introducing a database layer.

**Experiment manifests:**
- `data/smd_experiments/manifest.json` records batch-built experiment suites.
- Each generated case under `data/smd_experiments/cross_machine_*/*` or `data/smd_experiments/temporal_*/*` contains `split_metadata.json` plus the prepared `.npz` protocol files.
- These manifests are generated by `scripts/build_domain_shift_smd.py` and `scripts/make_uad_smd.py`.

**SWaT CSV integration:**
- `src/data/swat.py` parses raw SWaT CSV files and handles delimiter fallback, numeric coercion, scaling, and label extraction.
- `src/pipeline.py`, `run.ps1`, and `README.md` default to `data/SWaT/SWaT_Dataset_Normal_v1.csv` and `data/SWaT/SWaT_Dataset_Attack_v0.csv`.
- The current workspace also contains `data/SWaT/normal.csv` and `data/SWaT/attack.csv`, which are the defaults used by `scripts/run_usad_upstream_swat.py`.

**TS-TCC auxiliary datasets:**
- `data/UCI HAR Dataset/` contains the raw extracted UCI HAR text layout used by `src/ts_tcc/data_preprocessing/uci_har/preprocess_har.py`.
- `data/uci_har/source.npz` and `data/uci_har/target.npz` are local preprocessed arrays that fit the project-wide `.npz` workflow.
- `src/ts_tcc/data_preprocessing/epilepsy/data_files/data.csv` is checked in for the auxiliary Epilepsy pipeline.
- `scripts/preprocess_sleepedf.py` expects raw Sleep-EDF `.edf` files under `data/sleepedf_raw` and writes `data/sleepedf/source.npz` and `data/sleepedf/target.npz`.

**Observed file formats:**
- `.txt` for raw multivariate series and labels in `data/ServerMachineDataset/` and `data/UCI HAR Dataset/`.
- `.csv` for SWaT, Epilepsy, and legacy machine-folder layouts consumed by `src/data/swat.py` and `scripts/preprocess_smd.py`.
- `.npz` as the dominant interchange format for preprocessed windows, experiment splits, and auxiliary datasets across `data/` and `scripts/`.
- `.json` for manifests, metadata, result payloads, and benchmark summaries in `data/smd_experiments/` and `outputs/`.
- `.pt` and `.pth` for TS-TCC datasets and model checkpoints in `src/ts_tcc/`, `results/`, and `outputs/checkpoints/`.
- `.npy` for pseudo-label and pseudo-confidence diagnostics already present in `outputs/`.
- `.png` for exported figures in `outputs/figures/`.
- `.edf` for raw Sleep-EDF signals handled by `scripts/preprocess_sleepedf.py`.

## Local Services

**Process-local orchestration:**
- `scripts/run_all_smd.py`, `scripts/run_tranad_smd.py`, and `scripts/run_usad_swat.py` use `subprocess.Popen` to launch local Python jobs. They do not talk to a daemon, scheduler, or remote API.
- `run.ps1` performs the same orchestration in PowerShell by directly invoking `venv/Scripts/python.exe`.

## Data Storage

**Databases:**

**File Storage:**
